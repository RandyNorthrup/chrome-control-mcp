# The extension goes to the Chrome Web Store

Chrome Control MCP 1.13.0 publishes the Chrome extension to the Chrome Web Store, so adding it to
Chrome can be one click instead of Developer mode and a folder, and the store keeps it up to date.

## Two ways to add the extension

- **From the Chrome Web Store**:
  [Chrome Control MCP](https://chromewebstore.google.com/detail/mbkacllnbffbadcajpkkpelifdkfgcbd).
  Google reviews each version before the store offers it, so the store can trail a release by a few
  days, and the listing opens once its first review passes.
- **Unpacked**, as before: every archive still carries the extension folder, and `--install`
  prints its path.

Use one or the other in a Chrome profile, not both. The store build has an ID of its own,
`mbkacllnbffbadcajpkkpelifdkfgcbd`, beside the unpacked build's `iojehhmnaigcejfcpmilpclmeljhlkaa`.
The server answers to both and to no other extension: its native-messaging registration lists both,
and the relay checks the caller against the same two. The store build needs this server or later.

## Updating from 1.12

Nothing to do. A registration written by an older release lists only the unpacked build; 1.13.0
rewrites it -- on `--install`, on the VS Code extension's next start, on
`browser_extension_install`, and when the server itself starts, so an update applied with
`browser_update_apply` is covered too.

## Also in this release

- `browser_extension_status` reports the store build's ID as `store_extension_id`.
- `browser_new_tab` replies, and `browser_tabs` lists, only once the tab is in its agent's named
  group. A page that loads in milliseconds could see the reply first, and a listing straight after
  showed the new tab with no group.
- The extension has an icon, and a shorter description that fits the store's limit.
- The server's instructions give agents an order for looking at a page: `browser_find` for an
  element they can name, `browser_screenshot` to see the layout (about a thousand image tokens), and
  a whole `browser_snapshot` only for the full structure. An agent working through a cloud console
  had taken six snapshots of 12 to 20 thousand tokens each to find buttons a screenshot shows.
- A [privacy policy](https://github.com/RandyNorthrup/chrome-control-mcp/blob/main/docs/PRIVACY.md):
  what the extension reads goes to the server on the same computer and the client you connected;
  nothing is sent to the developer.
- Each release builds the store package -- the extension folder without the manifest's `key` -- and
  uploads and submits it through the Chrome Web Store API.
