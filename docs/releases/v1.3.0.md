Chrome Control MCP 1.3.0 makes `browser_upload` work on real pages. 1.2.x could attach a file to an
`<input type="file">`; this release can attach one on sites that hide that input, which is nearly
all of them.

## Changed

- **Upload works where the page hides its file input.** The pattern is universal: the real
  `<input type="file">` is set to `display:none` and a styled button, label, or menu item stands in
  front of it. A hidden element has no box and no accessibility node, so it had no `[ref]` -- and
  the tool whose whole job is to give that element a file had nothing to aim at. Two halves fix it,
  and either is enough on its own:

  - **A ref may name the control a person would click.** The search runs outward from whatever was
    named: the element itself, the input a label points at, one inside it, the input of an
    enclosing label, and finally the single file input of the nearest ancestor that has exactly
    one. A scope holding several is reported as ambiguous instead of guessed at, so a file is never
    attached to an input the caller did not name.
  - **The snapshot names file inputs whether or not the page shows them.** They are collected from
    the DOM after the accessibility pass and listed as `filechooser "name" [ref=eN] (hidden)`, with
    `multiple` flagged when the input takes several files. They are kept for naming only: they
    carry no box, so nothing can compute a click point from one, and the scan is capped like the
    media scan and reports truncation rather than hiding it.

  The search runs IN the page, and its source is inlined into the call rather than reimplemented
  there, so the function the unit tests exercise is the function the page runs.

## Verified

Windows 11 Pro 26200, MSVC 19.50, Qt 6.10.0, Node 24.13.0, Chrome for Testing 153.0.8010.52.

- 10/10 native and extension suites. Two new contract cases: a marked hidden file input survives
  the renderable filter and reaches the outline with a ref, and the exemption stays narrow -- a
  zero-area node that is not a marked file input, and a node that merely claims the role, are both
  still dropped.
- 70 service-worker unit cases, 11 of them new: every shape the web uses for a hidden input
  (label's control, `for`/id, wrapping button, sibling in a container), the ambiguity refusal, the
  collector's naming, de-duplication against the accessibility pass, its cap, and its refusal to
  report "no file inputs" when the scan itself failed.
- Live E2E on real Chrome: **44/44 tools across 158 reversible cases**, including uploads through
  a button that hides its input and straight into the hidden input by name, each asserting what the
  page read back.
- This release's own social preview image was set on GitHub with this tool, through the settings
  page's Edit menu -- the case that motivated the change.

Upgrade: replace the executable and the unpacked `extension` folder, then reload the extension once
from `chrome://extensions`. No native-host re-registration is needed; the manifest and extension ID
are unchanged.
