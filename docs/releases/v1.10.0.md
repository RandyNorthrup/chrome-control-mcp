# Chrome profiles, chosen per call

Chrome Control MCP 1.10.0 lets agents work in every Chrome profile you have -- work, personal,
each person's -- through one server, and choose which.

## Every profile at once

Chrome gives each profile its own copy of this extension, and each copy reaches the server through
a relay of its own. The server used to take exactly one relay, so it served whichever profile's
extension got there first; the other was turned away and kept trying for up to half an hour. Now
one server serves every profile you have loaded the extension in, up to eight, each on a connection
of its own: one profile reconnecting, reloading or closing never disturbs another's tabs.

## Choosing a profile

- **`browser_new_tab` takes a `profile`**, such as `"work"`, and opens the tab there. A name
  matches the profile's name or its account email, without regard to case; one that is not
  connected is refused with the names that are.
- **No profile named:** the tab opens in the profile whose Chrome window you used last. With one
  profile, everything works exactly as before.
- **Every call with a `tab_id` goes to the profile holding that tab**, so an agent picks a profile
  once, when it opens its tab. A ref goes where its tab is. A call naming no tab goes to the profile
  the last call went to.
- `browser_window` (to open a window), `browser_cookies` and `browser_permission` take `profile`
  too: cookies and site permissions belong to a profile.

## Seeing which is which

- A profile is called by its signed-in Google account's email, or a name you give it on the
  extension's options page (chrome://extensions, Chrome Control MCP, Details, Extension options) --
  "work", "personal". A profile that is not signed in gets a generated name until you name it. A
  new name takes effect at once.
- `browser_tabs` and `browser_windows` list every profile's tabs and windows, each with its
  `profile`. `browser_release` without a `tab_id` lets go in every profile.
- `browser_extension_status` lists every connected profile with its name, email and versions, and
  a version note says which profile it is about.

## What it asks for

Naming a profile by its account email needs the `identity` and `identity.email` permissions, which
this extension did not have; that email is shown to agents, and through them to the AI service they
use. Rename a profile to keep its email out of it. A profile without the extension is invisible to
agents, so load it only where agents should work.

Profiles of two different Chromes at once -- two installs, or two user data directories -- are not
served together: tab ids are unique only within one Chrome, so the second is refused, saying why.

## Updating

- From 1.9.0, the extension reloads itself into this version once no agent is using it. Measured:
  an extension reloading into the new permissions comes back enabled. Coming from 1.8.x, press
  reload on Chrome Control MCP at chrome://extensions once.
- To use another profile, load the extension there too: in that profile, open chrome://extensions,
  turn on Developer mode, choose Load unpacked, and pick the same folder.
- Restart any editor or agent that was running before the update, so it starts the new server.
