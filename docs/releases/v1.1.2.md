Chrome Control MCP 1.1.2 is 1.1.1 with one comment rewrapped. The 1.1.1 commit failed the
`clang-format` gate on a comment added with the fix below, and a released commit should be green,
so this release carries the same program past the same gates.

Everything 1.1.1 changed is in this release. Its notes are in
[`docs/releases/v1.1.1.md`](v1.1.1.md):

- **A screenshot of a background tab returns** instead of waiting out the transport deadline and
  taking the session's bridge down with it. Captures of a tab that is not on screen run with a
  one-pixel screencast, which is what makes Chrome composite that tab, and every capture path is
  bounded well inside the deadline. The image is the same one: at 2x, foreground plain capture and
  background forced capture are byte-identical.
- **The live suites' dedicated browser runs on Windows**, which is what found that hang.
- **`browser_extension_install` states that loading the unpacked extension is manual and cannot be
  automated**, in its description and in its reply, so an assistant hands the step to the user.

## Verified

Rebuilt and re-run at 1.1.2 on Windows 11, MSVC 19.50, Qt 6.10.0, Node 24.13.0: 9/9 native and
extension suites, 52 service-worker unit cases, smoke listing 43 tools as server version `1.1.2`,
and the full live E2E at **43/43 tools over 151 reversible cases** on a real Chrome, with the whole
pre-commit gate set clean. Full evidence is in `docs/VERIFICATION.md`.

Upgrade: replace the executable and the unpacked `extension` folder, then reload the extension once
from `chrome://extensions`. No native-host re-registration is needed; the manifest and extension ID
are unchanged.
