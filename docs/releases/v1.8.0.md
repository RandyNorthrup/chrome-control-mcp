# Agents share one browser without touching each other's tabs

Chrome Control MCP 1.8.0 lets several agents share one browser without touching each other's tabs,
keeps your own tabs yours, and cleans up after itself. Every change here came from daily use with
more than one agent at a time.

## A second editor could go hours without the browser

With two servers running, one could sit unattached all day. Its pipe has a single instance, and the
server only looked at it when it sent a command: when its relay died with a Chrome restart, it held
that dead connection until its next tool call, and every relay in between was refused with "pipe
busy". An idle server now notices within a quarter of a second and listens again. Relays offer only
servers that are running, and an attached relay tells the extension when a new server starts, so it
is picked up in about a second -- without the extension starting a process to look.

## Agents keep to their own tabs

Agents that share one server -- sub-agents, parallel tasks of one client -- used to share one
"current tab" and one set of element refs, so one agent opening a tab moved the next click of
another. Now:

- `browser_new_tab` returns a `tab_id`, and every tab-scoped tool takes `tab_id`.
- Element refs are bound to the tab their snapshot came from and are never reused, so a ref always
  acts on its own tab.
- `agent` on `browser_new_tab` gives an agent its own tab group, named for it (**AI · research**),
  in a colour no other group has. The frame and badge on the page use the same colour and name.
- The server tells any MCP client how to share the browser through the standard `instructions`
  field, so this works the same in every client.

## Your tabs stay yours

Pressing Ctrl+T, or middle-clicking a link, while an AI tab was in front pulled your new tab into the
AI group and moved the assistant onto it: Chrome names the tab you were looking at as the new tab's
opener. A tab is now the assistant's only if it opened it, its own action opened it, it was given it,
or you dragged it into the AI group. Drag a tab out of the group to take it back.

## Cleaning up

- `browser_release` closes the tabs an agent opened and hands back any it borrowed. Borrowed tabs
  are never closed, and neither is the tab you are looking at or the browser's last tab.
- When an agent's server exits, its tabs are released the same way.
- After ten minutes without a command, an agent's tabs are stood down -- no highlight, no debugging
  bar, the group greyed and marked idle -- and its next command picks them back up.
- Every tab an agent holds is highlighted, not only the one it is driving, and the highlight is drawn
  into each new page as it loads.

## Found by using it

Three faults only a real browser showed, each now covered by a test:

- The highlight broke on pages that enforce Trusted Types (YouTube, Gmail, Google Docs): its cursor
  was built with `innerHTML`, which those pages refuse. It is built node by node now, and no longer
  leaves an error in the page's console for `browser_console` to report as the page's own.
- A link that opens a new tab left that tab behind as a stray, in front of you. It now joins the
  agent's group, and the tab you had in front stays in front.
- A Chrome error or warning page ("Privacy error") answered with a bare "Cannot attach to this
  target"; the reply now says what the page is.

## File pickers without dialogs

Chrome cancels a file dialog in a tab that is not in front, and shows one over your work when it is.
While an agent's command is running, a page's request for a file is now caught instead:
`browser_upload` with no `ref` fills the input a script created and clicked, a `showOpenFilePicker`
call, or -- given the zone's ref -- a drag-and-drop zone. Your own clicks still get the normal dialog.
Folder pickers are not supported yet.

## Updating

- The extension and the server speak a new bridge protocol, so both must be 1.8.0. A Chrome still
  running the old extension reloads it once by itself; if it does not, reload it at
  chrome://extensions.
- Restart any editor or agent that was running before the update, so it starts the new server.
- Opening an editor no longer rolls an update back to the version the editor bundles.
- The extension asks for two new permissions: `webNavigation`, to tell which tab a new tab was
  opened from, and `scripting`, used only to remove the highlight from a
  page the debugger can no longer reach.
