Chrome Control MCP 1.1.0 makes the assistant a tab of its own. It works in a tab the user is not
looking at, without taking that tab to the front, without taking OS focus, and without ever hiding
itself: the tab it drives is marked in the tab strip with a pink `AI CONTROL` group, the same pink
as the frame drawn on the page. Coordinates read off a screenshot now land where they are aimed at
any display scale, any browser zoom step, and under a trackpad pinch.

## Changed

- **The session drives its own tab.** It pins that tab instead of re-resolving "the active tab of
  the last focused window" on every call, so a user switching tabs or windows mid-session no longer
  redirects the assistant's next click, keystroke, or snapshot onto the page they are reading.
- **The user's view is never changed.** `browser_new_tab` opens in the background and
  `browser_select_tab` retargets the session without activating the tab. A closed session tab is
  not replaced by a neighbour -- every neighbour is a tab the user may be using -- so the session
  reports it has no tab until it is given one.
- **The controlled tab is always visible.** It sits in a pink `AI CONTROL` tab group that is never
  collapsed and follows the session; a tab the user had already grouped is left in their group.
  Background means Chrome is not painting it; it never means concealed.
- **OS focus is never taken.** `browser_select_tab` does not raise its window, `browser_window`
  `new` opens with `focused: false`, and `focus` retargets the session without raising anything.
  CDP focus emulation keeps focus-gated pages working while Chrome is in the background. A
  compositor that focuses a new window anyway (Hyprland) is reported as `took_os_focus: true`
  rather than passed over.
- **`browser_scroll` replies once the page has come to rest**, with `scrolled`: how far the content
  actually moved, 0 at an edge. A wheel scroll is animated, so a screenshot taken on the old reply
  could catch the page mid-flight.

## Fixed

- **Coordinates off a screenshot land where they are aimed.** `browser_drag`'s endpoints were
  dispatched as CSS pixels while a model can only read coordinates from a screenshot, so every drag
  missed by the display scale, zoom, and pinch on any display but an unzoomed 100% one. They are
  now screenshot pixels, converted exactly as `browser_click_at` converts them and bound to the
  same screenshot. `browser_box` gained `screenshot_center`, and `browser_emulate` accepts the
  fractional `device_scale_factor` values (1.25, 1.5, 1.75) that most Windows desktops use.
- **A trackpad pinch no longer moves every target.** A pinch moves what is on screen without
  changing the scroll offset, zoom, or viewport size the screenshot was bound to. The render
  fingerprint now carries the pinch's scale and offset and every conversion goes through it, so a
  coordinate click after a pinch no longer lands at the unpinched position, `screenshot_center`
  accounts for it, and the occlusion test stops refusing clicks on elements nothing covers.
- **Full-page screenshots at any browser zoom.** Chrome reads the capture clip in DIPs, not CSS
  pixels: the capture came out twice the document at 50% zoom, cut it short at 110% and above, and
  failed outright on a small window at 25%. A full-page capture of a pinched page is now refused
  instead of silently resetting the user's pinch, which nothing can put back.
- **A background tab is no longer slow.** Chrome coalesces a background extension service worker's
  timers into seconds, while the same page's own timers keep time to the millisecond, and it
  answers continuous input at a frame. Every wait about the page is now timed by the page, and a
  drag's interpolated moves are sent in order and awaited together. Measured per call on a real
  hidden tab: drag 8,883 ms → 103 ms, scroll 10,133 → 52, hover with `duration_ms: 100` 6,255 →
  155, `browser_wait_for` with a 1.5 s timeout 10,273 → 1,553, `browser_window` `new` 10,904 → 286.
- **Nothing reports success it did not achieve.** A coordinate read off a screenshot must be inside
  it; an element that could not be brought on screen is refused rather than clicked off the
  viewport; an unreadable scroll offset or pinch fails the read instead of counting as zero; a hit
  test that names no node is refused rather than read as "nothing is in the way"; a screenshot says
  whether the control overlay is actually in the image; `browser_http_auth` `clear` surfaces a
  failure to stop intercepting; `browser_download` says which state a download ended in; and
  `browser_hover`'s `duration_ms` and `browser_drag`'s `steps`/`hold_ms` refuse a value they cannot
  honour instead of silently becoming the default.
- **`browser_click` by ref tries the part of an element a user would click**, instead of refusing
  when the centre alone is covered, and waits out the macOS overlay scrollbar that its own scroll
  into view raises, re-measuring the element each time. When no point of it takes a click, it says
  so rather than naming `<html>`.
- **A drag that fails halfway releases where the pointer actually got to**, and `browser_scroll`'s
  `scrolled` counts each scroller once and matches them by name.

## Verification

- 9/9 native and extension suites, macOS (Clang, Qt 6.11.1, Node 26.5) and the Windows, Linux, and
  macOS CI matrix; warnings as errors, clang-tidy, cppcheck, Semgrep, ASan/UBSan and TSan gates.
- Staged MCP smoke on the release build: 43 tools listed, server version `1.1.0`.
- Live on the user's own Chrome 153, every call in a tab nobody was looking at: **43/43 tools, 151
  reversible cases**, with the user's tab asserted to still be in front after every single call and
  the machine's front application unchanged.
- Live display matrix in dedicated browsers: **35/35 configurations, 3,335/3,335 checks** across
  display scales 1×–3× (including 1.25×, 1.5×, 1.75×, 2.5×), windows from 390×844 to 3840×2160,
  every Chrome zoom step from 25% to 500%, trackpad pinch at 1.5×, 2×, and 3×, and both an overlay
  scrollbar and one that takes layout space. Every coordinate is proven by where its click landed
  on the fixture, every screenshot by the pixels of its colour targets measured against the page's
  own `getBoundingClientRect`.
- Live user-interference suite: **10/10 checks**. A tab and then a window opened as the user;
  snapshots, typing, screenshots, scrolling, and clicking stayed on the session's tab, and the
  session opened no windows of its own.
- Full evidence, including the before/after timings above, is in `docs/VERIFICATION.md`.

Upgrade: replace the executable and the unpacked `extension` folder, then reload the extension once
from `chrome://extensions`. No native-host re-registration is needed; the manifest and extension ID
