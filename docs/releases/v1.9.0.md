# A clipboard for every agent

Chrome Control MCP 1.9.0 gives every agent a clipboard of its own, and keeps all of them away from
yours.

## A clipboard each

Agents used to share the one clipboard your computer has. One agent's Ctrl+V pasted another
agent's copy, or yours -- whatever you had copied last, a password included -- and every copy an
agent made replaced what you had copied. A page's own "Copy" button clicked by an agent wrote your
clipboard too.

Now each agent has its own clipboard, kept by the extension in memory, never written anywhere, and
emptied when the agent lets go of its last tab. Nothing an agent does reads or writes yours:

- **Copy, cut and paste keys** an agent presses use its own clipboard.
- **`browser_clipboard`** puts text, formatting or images on it, reads it back, or clears it, and
  copies, cuts and pastes -- so an agent preparing a post or attaching an image no longer needs a
  shell clipboard command that every other agent and you share.
- **A page's own copy and paste buttons**, in a tab an agent is using, use that agent's clipboard
  while the agent is acting on the page, and are refused at any other time.

## Pastes like a person

A paste reaches the page the way your own Ctrl+V does: a `paste` event carrying the text, the
formatting and any image, then the `beforeinput` event some editors read instead. Checked live on
the editors real sites are built with -- ProseMirror, Lexical, Slate, Quill, Draft.js, CKEditor 5
and CodeMirror -- and in a plain form field, an editor inside a frame, and a field inside a frame
from another site, where the text is typed in. If a page takes neither event, the text is typed in,
line by line with Shift+Enter, so a paste never sends a chat message.

## Told when Chrome is running an old extension

An update replaces the server and the extension's files together, but Chrome keeps running the
extension it loaded until it is reloaded, and until now nothing said so. A user who updated to
1.8.2 and did not reload kept the very `browser_release` bug 1.8.2 fixed.

- The extension now says its version when it attaches, and the server compares it with its own and
  with the installed copy. When they disagree, your agent's first browser reply on that connection
  carries one more note -- after the reply, so nothing that reads the reply changes -- naming the
  versions and the fix: reload the extension, restart the server, or install this build. It works
  in every MCP client, and `browser_extension_status` shows the same under `running`.
- From 1.9.0 on the extension reloads itself for a newer installed copy, once no agent holds a tab
  and none has used it for 10 s, and only once per version.
- A command an older extension does not know -- `browser_clipboard` against 1.8.x -- says the
  extension is older and how to reload it, instead of only "Unknown command".

## Also fixed

- `Shift+Insert` and `Control+Insert` were refused as an unsupported key.
- An upload the server then rejected had already sent its file to the extension, which held it until
  the session ended. Arguments are now checked first.
- Release pages, this one and every one before it, are titled with what the release does, say the
  day it shipped, and say which download is yours. The changelog opens with every release and its
  date, and the README has a What's new section.

## Updating

- Coming from 1.8.x, press reload on Chrome Control MCP at chrome://extensions once after
  updating (or restart Chrome): a 1.8.x extension cannot reload itself, and your agent's first
  reply will remind you. From 1.9.0 on the extension does this by itself.
- Restart any editor or agent that was running before the update, so it starts the new server.
