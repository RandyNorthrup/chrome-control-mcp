Chrome Control MCP 1.8.1 fixes what a day of using 1.8.0 turned up, and restores two quality gates
that had quietly stopped running.

## Fixed

- **Uploads report what they delivered.** On a page that reads the file and then empties its input
  -- GitHub's uploaders do -- `browser_upload` answered `files: []` for an upload that worked. The
  reply now lists the files delivered and says `page_cleared_input: true` when the page reset its
  input.
- **Agent names in any script.** `agent: "café"` titled the group `caf`, and a name with no ASCII
  at all, such as `研究`, put the agent's tabs in the shared group. Names are kept as given; control
  and format characters are still dropped.
- **Agent colours are easier to tell apart.** Groups are coloured pink, cyan, orange, blue, green,
  yellow, red, then purple; purple used to come second, right beside pink.
- **The instructions sent to every MCP client** no longer say every held tab has a pink frame. The
  frame is in its group's colour.

## Quality gates

- **Semgrep runs again.** The CI step that installs Qt had switched the analysis job to Python 3.15,
  where Semgrep's engine crashes before scanning; the job now keeps its pinned Python 3.12, under
  which the scan is clean.
- **The tab-handling unit tests run in CI.** `test_browser_extension_tabs` and
  `test_release_versions` ran only locally; they are now part of ctest on Windows, Linux and macOS.
- **A timing-sensitive relay test** gained the margin it needed on a busy runner, and now names the
  cause first if it fails.

## Docs

The README, the VS Code Marketplace page and every document under `docs/` are rewritten for 1.8,
with a new banner, social preview, and screenshots of three agents from two clients sharing one
window.

## Updating

- The bridge protocol is unchanged, so the extension does not reload itself: press reload on
  Chrome Control MCP at chrome://extensions after updating.
- Restart any editor or agent that was running before the update, so it starts the new server.
