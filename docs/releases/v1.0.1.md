Chrome Control MCP 1.0.1 is a maintenance release: the browser bridge now heals itself when a
concurrent server instance takes or removes its discovery record, so an assistant session no longer
has to be restarted to get its browser back.

## Fixed

- **Bridge lost to a startup race.** Some MCP hosts launch the server twice within milliseconds
  (a short-lived tool listing beside the long-lived session). Both instances passed the live-owner
  check before either wrote the rendezvous record; the short-lived one wrote last and, naming its
  own pid, removed the record on exit. The long-lived server was left listening on a pipe nothing
  could discover, and every browser tool reported "not attached" for the life of the session.
  - `BrowserBridgePipeServer::ensurePublished` re-publishes the record when it is missing or names
    a server that has exited, and refuses when another live server of the same image owns it.
  - `BrowserControl::invoke` retries the bridge start when the server stood down at launch and
    calls `ensurePublished` before each browser tool call while no relay is connected.
  - The browser tools stay listed when the bridge could not start at launch; the failure is
    reported per call with the reason (including the owning pid) instead of hidden at startup.
  - The extension re-arms the native bridge from a 30-second `chrome.alarms` alarm, so a service
    worker Chrome has retired still reconnects once a server publishes its record. The unpacked
    extension gains the `alarms` permission; reload it once from `chrome://extensions`.
  - Three new pipe-server unit tests cover the lost record, a record left by an exited server, and
    a server that is not running. Windows and POSIX backends both covered.

## Verification

- 9 native and extension suites on Windows (MSVC, Qt 6.10.3), warnings as errors
- Staged MCP smoke: 43 tools listed, `browser_extension_status` answered
- Live: a session whose server had lost the record re-published it, the extension's relay
  reconnected within seconds, and `browser_tabs` listed the operator's tabs
- The tag workflow rebuilds and tests every archive on clean GitHub-hosted runners

Upgrade: replace the executable and the unpacked `extension` folder, then reload the extension.
No native-host re-registration is needed; the manifest and extension ID are unchanged.
